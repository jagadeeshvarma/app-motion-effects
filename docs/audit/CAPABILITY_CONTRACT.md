# Capability contract and frozen evaluation boundary

`app-motion-effects` helps a coding agent audit, implement and visually verify purposeful motion, transitions and interaction feedback in an actual product while preserving its brand, architecture, state and requested scope.

Activate for explicit app motion/effects work, a broad motion pass, a focused interaction improvement or a requested motion audit/mockup. Remain inactive for unrelated backend, infrastructure, correspondence and general knowledge tasks. A request without useful motion/feedback work does not justify a full design pass.

Inputs are the user task, applicable project instructions, actual source/design context and available authorised tools. Output is working app-specific code or the requested audit/mockup, appropriate validation, a runnable preview/evidence and precise limits. A focused bug remains focused. The skill does not authorise purchases, data access, account changes, commits, merging or deployment of future users' apps.

The portable core is Markdown/YAML/reference text. Codex and Claude Code have separate documented discovery adapters; format readability is not runtime compatibility. This audit measures the installed authenticated Codex CLI. Claude Code execution is currently blocked by absent authentication. Other hosts remain untested unless separately exercised.

Web and native mobile are required goals within motion/UI scope. Native evidence will distinguish source guidance, Flutter widget tests, platform builds, simulator/emulator playback and hardware. React Native and other catalogue entries remain version-dependent guidance unless actually evaluated. No browser screenshot establishes a native result.

Unavailable optional tools should lead to suitable existing primitives and an honest evidence boundary. Missing required permissions/runtime is a blocker for that operation; it is not success or permission to bypass controls. Backend/auth contracts are inspected to reflect true UI outcomes, not silently redesigned.

Acceptance IDs and sample plan are frozen in `acceptance.json` before skill behaviour changes. Development tasks and held-out tasks are separate. Baseline inventory and release identity are in `baseline.json`. The prior website task was fully published and verified before this audit began.
